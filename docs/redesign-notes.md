# 新版前端说明（给接手的人看）

> 这份说明对应合并请求 #1（`redesign` 分支）。讲三件事：改了什么、哪些不是真实数据、还差什么。

## 一、直接看效果

不用装东西，点开就行：

- 首页：https://geo-check-seven.vercel.app/
- Bao Noodle House（52 分）：https://geo-check-seven.vercel.app/#k=baonoodlehouse.com
- Easy Joy（77 分）：https://geo-check-seven.vercel.app/#k=easyjoybuffet.com

本机预览和以前一样：`python3 serve.py`，然后打开 http://localhost:8000/ 。

## 二、动了哪些文件

| 文件 | 改动 |
|---|---|
| `index.html` | 重写。首页 + 报告页的骨架 |
| `static/story.css` | 重写。样式 |
| `static/story.js` | 重写。页面逻辑和动画 |

| `static/sample-hours.js` | **新增**。营业时间的示例数据，见第五节 |

读数据的方式也没有变：

```
POST /api/check {url}      → {key} 或 {error}
GET  /api/result?key=<店>  → result.json；status 不是 done 就每 1.5 秒再读一次
GET  /api/tile?z=&x=&y=    → 地图底图
```

## 三、页面结构

**首页**（`#v-home`）：首屏（输入框 + 打字演示）→ 替你做三件事 → 什么是 GEO（以前 / 现在）→ 平台滚动带 → 报告展台（叠卡）→ 底部行动区。

**报告页**（`#v-report`）：一屏只讲一件事。

| 屏 | id | 用到 result.json 的哪些字段 |
|---|---|---|
| 封面 | `#r-cover` | `store`、`portrait`（照片、常提的菜、客人原话） |
| 1 得分 | `#r-score` | `score.total`、`score.dims` |
| 2 AI 怎么说 | `#r-ai` | `questions[].engines`（每次提问的回答和名单）、`rivals` |
| 3 AI 看哪里 | `#r-src` | `source_groups`、`sites` |
| 4 地图 | `#r-map` | `grid.cells`，底图走 `/api/tile` |
| 5 平台 | `#r-pf` | `platforms.rows`（有没有、电话地址对不对）、`rival_platforms` |
| 6 口碑 | `#r-rep` | `store` 的评分和评价数、`rivals` |
| 7 总结和下一步 | `#r-next`、`#r-plan` | `score.dims`、`actions` |
| 联系我们 | `#r-contact` | 没有数据，内容是占位的 |

**加载**不是单独一页，就在报告页上演：先照着真实排版画骨架，数据到一块亮一块。

## 四、网址上的开关

| 写法 | 作用 |
|---|---|
| `/#k=<店>` | 直接打开那家店的报告 |
| `?static` | 跳过加载动画 |
| `?demo=bad` | 预览「电话、地址对不上」时的样子（只在浏览器里临时改，不动数据） |
| `?hours=ok` | 预览「营业时间全部一致」时的样子 |

开关写在 `#` 前面，例如 `/?static#k=baonoodlehouse.com`。

## 五、哪些不是真实数据（重要）

页面上有四处不是测出来的。每一处在页面上都标了「估算」或「示例数据」。

1. **预计加几分**（下一步那一屏）
   `actions` 里没有分数，是前端估的：把对应那一项补到 70 分能加多少。算式在 `story.js` 的 `build()` 里，找 `gain`。后台以后给出真实加分，直接替换这一处。
2. **Easy Joy 的对手评分和评价数**（口碑那一屏）
   Easy Joy 的数据里对手没有评分，用的是示例数字。数据补上后页面会自动用真实的。
3. **营业时间核对**（平台那一屏最下面）
   后台现在只核对了电话和地址。示例数据在 `static/sample-hours.js`。
   以后在 `platforms.rows[]` 每一行加 `hours` 字段（格式同 `store.hours`），页面会自动用真实的，这个文件可以删掉，`index.html` 里对应的 `<script>` 也一起删。
4. **加载的节奏**
   演示版的数据是一次读完的，一屏一屏亮出来是按固定时间演的。
   正式版数据陆续回来时：哪一块到了，调一次 `ldShow('<那一块>')`。一共七块：`store`、`photo`、`rev`、`pf`、`map`、`ai`、`score`。见 `story.js` 的 `runLoad()`。

## 六、想改东西去哪里找

- **改文字**：全在 `static/copy.js`。`{name}` 这样的写法是占位，运行时换成真实的值。
- **改颜色**：`static/story.css` 最上面的变量。品牌橙是 `--accent: #FF770F`。
- **改某一屏**：`static/story.js` 按屏分了段，每段开头有中文注释：

  | 行 | 内容 |
  |---|---|
  | 19 起 | 首页 |
  | 127 起 | 报告页 |
  | 146 | `build()`：把 result.json 整理成页面要用的样子 |
  | 220–446 | 封面、1 得分 … 7 总结和下一步，一屏一段 |
  | 447 | 目录条、进入动画、数字跳动 |
  | 482 | 加载和骨架 |
  | 586 起 | 页面切换 |

- **改完记得**：`index.html` 里 css 和 js 链接后面的 `?v=13` 加 1，不然浏览器会用旧缓存。

说明一点：`story.js` 和 `story.css` 写得比较紧凑，有些行很长。如果读起来费劲，用格式化工具（比如 Prettier）跑一遍就行，不影响功能。
